Questionamentos 2:
Você tem apenas X, Y, H visíveis para o programador. H é só rascunho interno. Na prática o assembler tem 2 registradores de propósito geral.
Impacto: Força uso de memória para guardar temporários, custando 2–3 ciclos por acesso (MAR, READ/WRITE, MDR).
Solução: Adicionar registradores, por exemplo Z1, Z2 (evitando conflito com seu flag Z). No layout do MIR você tem 3 bits para BUS_A e 3 bits para BUS_B — isso suporta até 8 fontes cada, e hoje você só usa 6. Sobram 2 slots livres em cada barramento.



Problema: a & b e a | b existem, mas ambos os operandos vêm de registradores. Não existe forma de fazer X & 1 sem antes carregar 1 num registrador ou na memória.
Impacto direto: Impossibilita testar bits individuais de forma eficiente — bloqueia shift-and-add, máscaras, flags de paridade.
Solução: Adicionar uma constante implícita na ALU. Dois caminhos:
Simples: Adicionar o = a & 1 e o = a | 1 como operações novas (aproveitando bits [7:6] do campo ALU que você usa para shift — reorganizando).
Melhor: Adicionar um registrador IMM (imediato) que o fetch carrega com o próximo byte, similar ao MBR mas para operandos, não endereços.


Campo ALU — Bits desperdiçados
Problema: O campo ALU tem 8 bits, mas shift ocupa os 2 mais significativos [7:6] e a operação usa 6 bits [5:0]. Porém, dos 64 valores possíveis nos 6 bits, você usa apenas 16 operações. Sobram 48 combinações sem uso.
Solução: Usar combinações livres para operações compostas úteis como:

a & 1 — testa bit 0 (essencial pra multiplicação)
a XOR b — muito útil, hoje ausente
|a| — valor absoluto
a & 0xFF — máscara de byte



Flags N e Z — Só atualizadas pela ALU
Problema: N e Z são atualizados a cada operação ALU, mesmo quando você não quer (ex: ao mover dados com ALU=B para carregar MAR, você sobrescreve as flags acidentalmente).
Impacto: Em sequências como "carrega endereço, lê memória, testa resultado", as flags do teste podem ser corrompidas pelo ciclo de carga.
Solução: Adicionar 1 bit no MIR chamado SAVE_FLAGS — quando 0, a ALU opera mas não atualiza N/Z. Só custa 1 bit no MIR.



  Quem está fazendo o papel do IR, de forma adaptada, é o MBR (Memory Byte Buffer Register).

Vou te explicar exatamente o porquê disso estar acontecendo e como o seu circuito funciona:

Por que o MBR virou o "IR"?
Em um processador completo e maior, o fluxo normal seria:

Buscar o opcode na memória usando o endereço do PC.

Jogar esse dado no MBR.

Copiar o conteúdo do MBR para o IR.

A Unidade de Controle lê o IR para decidir qual microprograma rodar.

Porém, como este modelo é uma simplificação didática baseada em instruções de 1 byte de opcode (como dá para ver no seu firmware[0] e firmware[10]), os projetistas cortaram caminho para economizar hardware (e código). O valor do opcode lido da memória RAM fica guardado diretamente no MBR e é consumido dali mesmo!

A prova disso no seu próprio código
Destaquei duas partes do seu código onde o MBR age exatamente como se fosse o IR (guardando a macro-instrução para decidir o desvio do firmware):

1. Na instrução de FETCH (firmware[0])
Python
# 0: INIT
firmware[0] = 0b000000000_100_00110101_001000_001_001 
# BUS_C = PC + 1; PC = BUS_C; MBR = memory.read_byte(PC) (FETCH); GOTO MBR.
Aqui, o processador lê a próxima macro-instrução do usuário e joga no MBR. Logo em seguida, ele faz um GOTO MBR. Pular para o valor que está no MBR significa usar o opcode guardado nele para indexar o firmware (ex: se o programa do usuário leu 2, o MPC vai saltar direto para o firmware[2]). Isso é pura decodificação de instrução, o papel clássico do IR!

2. Na função next_instruction
Python
if jam & 0b100:
    nextadd = nextadd | MBR
O bit de JAMN (ou JMPC) ativa essa linha. Ela faz um OR binário entre o endereço base e o conteúdo do MBR para forçar o MPC a ir para a linha do firmware correspondente à instrução que o usuário mandou rodar.

Resumo da ópera
Neste computador que você está emulando:

O MBR tem dupla identidade: ele serve tanto para segurar os dados temporários que vêm da memória quanto para segurar o Opcode da Macro-instrução atual.

Portanto, o MBR e o IR são o mesmo registrador na prática.
